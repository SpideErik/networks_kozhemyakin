# Домашняя работа по теме HTTP-заголовки, статус-коды, MIME и кеширование

## 1. Дай определение терминам:

1. **HTTP** (расшифруй и объясни назначение)
> Hyper text transfer protocol - протокол передачи гипертекста. Прикладной протокол (OSI уровень 7), предназначенный для обмена данными между клиентом и сервером в сети. Изначально он использовался преимущественно для передачи HTML-документов, но сейчас применяется для передачи различных ресурсов: изображений, файлов, JSON-данных и других типов содержимого.

2. **HTTPS** — чем отличается от HTTP?
> HTTPS — это защищeнная версия HTTP, в которой обмен данными осуществляется с использованием TLS (Transport Layer Security). TLS обеспечивает шифрование передаваемых данных, проверку подлинности сервера и защиту целостности сообщений. Поэтому HTTPS безопаснее HTTP, при котором данные передаются без встроенного шифрования. TLS работает между прикладными протоколами и транспортным уровнем.

3. **Клиент-серверная модель** — что это?
> Клиент-серверная модель — это архитектура взаимодействия, при которой клиент отправляет запросы серверу, а сервер обрабатывает их и возвращает ответы. Клиентом может быть браузер или мобильное приложение, а сервером — программа, которая обрабатывает запросы, выполняет бизнес-логику и при необходимости взаимодействует с базой данных. Клиент обычно отвечает за взаимодействие с пользователем, а сервер — за обработку данных и выполнение основных операций.

4. **Идемпотентность** — что означает?
> Идемпотентность — это свойство операции, при котором её повторное выполнение с теми же параметрами приводит к тому же результату, что и однократное выполнение, с точки зрения предусмотренного эффекта операции. В HTTP идемпотентные методы позволяют повторять запросы без дополнительного эффекта от повторения. Например, многократный запрос на получение ресурса не изменяет его состояние, а повторный запрос на установку определённого значения не должен приводить к дополнительным изменениям после первого выполнения.

>Уточнения:
>- Идемпотентность не означает, что ответ обязательно будет одинаковым при каждом запросе.
>- Идемпотентность сама по себе не позволяет кешировать ответы. Кеширование регулируется отдельными правилами HTTP.
>- К идемпотентным HTTP-методам относятся `GET`, `HEAD`, `PUT`, `DELETE`, `OPTIONS` и `TRACE`. Методы `POST` и `PATCH` по умолчанию не гарантируют идемпотентность.

>Например, если отправить `DELETE /users/5` несколько раз, пользователь с идентификатором `5` будет удалён при первом успешном запросе, а последующие запросы не должны приводить к дополнительному эффекту удаления. При этом HTTP-статусы ответов могут отличаться.


## 2.1. Разбери запрос

### Дан HTTP-запрос:

```http
POST /api/users HTTP/1.1
Host: example.com
Content-Type: application/json
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
Content-Length: 58

{"name": "Иван", "email": "ivan@mail.com"}
```

Ответь на вопросы:

1. Какой метод используется?
> `POST` — метод HTTP, обычно используемый для отправки данных на сервер, например для создания нового пользователя.

2. Какой путь (endpoint) запрашивается?
> `/api/users` — путь к ресурсу API, с которым взаимодействует клиент. В данном случае он указывает на ресурс пользователей.

3. Какая версия HTTP?
> `HTTP/1.1` — версия протокола HTTP, указанная в стартовой строке запроса.

4. Что означает заголовок Content-Type?
> `Content-Type: application/json` указывает тип содержимого тела запроса. `application` — категория типа данных, а `json` — формат представления данных. Это означает, что тело запроса содержит данные в формате JSON.

5. Что означает заголовок Authorization?
> `Authorization: Bearer ...` — заголовок, передающий данные для авторизации или аутентификации клиента. `Bearer` — схема передачи учётных данных, при которой доступ предоставляется на основании предъявленного токена. В данном случае передаётся токен, который сервер должен проверить.

6. Где находится тело запроса?
> Тело запроса находится после пустой строки, отделяющей заголовки от тела. В данном примере это JSON-объект с полями `name` и `email`. Заголовок `Content-Length: 58` указывает длину тела запроса в байтах.

### Дан HTTP-ответ:

```http
HTTP/1.1 201 Created
Content-Type: application/json
Location: /api/users/42

{"id": 42, "name": "Иван", "email": "ivan@mail.com"}
```

Ответь:

1. Что означает статус-код 201?
> Коды состояния от `200` до `299` означают успешное выполнение запроса. Код `201 Created` указывает, что запрос выполнен успешно и в результате был создан новый ресурс. В данном случае сервер создал пользователя.

2. Зачем нужен заголовок Location?
> Заголовок `Location` указывает адрес созданного ресурса — `/api/users/42`. В данном случае он позволяет определить, по какому пути можно обратиться к созданному пользователю с идентификатором `42`.

3. Что находится в теле ответа?
> Тело ответа отделено от заголовков пустой строкой и содержит данные в формате JSON. В данном примере сервер возвращает информацию о созданном пользователе: его идентификатор (`id`), имя (`name`) и адрес электронной почты (`email`).

## 2.3. Собери запрос сам

Составь HTTP-запрос для:

* Получения списка всех товаров

```http
GET /api/goods HTTP/1.1
Host: example.com
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
```
> Т.к. запрос всех товаров - тело запроса не требуется, а Content-Type можно не указывать

* Создания нового товара с именем "Ноутбук" и ценой 50000

```http
POST /api/goods HTTP/1.1
Host: example.com
Content-Type: application/json
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
Content-Length: 43

{"name": "Ноутбук", "price": 50000}
```


* Удаления товара с id=7

```http
DELETE /api/goods/7 HTTP/1.1
Host: example.com
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
```

* Обновления товара с id=3 (изменить цену на 45000)

```http
PATCH /api/goods/3 HTTP/1.1
Host: example.com
Content-Type: application/json
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
Content-Length: 17

{"price": 45000}
```
